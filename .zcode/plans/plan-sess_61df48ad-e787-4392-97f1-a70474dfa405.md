## 2. Database (apply_migration)
- **`site_events`** — one row per event (`pageview`, `section_view`, `scroll`, `click_out`, `engage_end`):
  - identity: `visitor_id` (persistent localStorage UUID), `session_id` (30-min window)
  - page context: path, title, referrer, `utm` jsonb (utm_* + gclid from query string)
  - client env: language, timezone, screen/viewport w+h, DPR, color scheme, touch, hardwareConcurrency, deviceMemory, connection type, webdriver (bot flag)
  - server-captured: `user_agent`, `ip` (inet), accept-language
  - geo (IP-derived): country, region, city, lat/lon, ASN, org
  - UA-parsed: browser + version, engine, OS + version, device type/vendor/model, `is_bot`
  - `props` jsonb (scroll %, visible-seconds, link href/text, section)
- RLS **enabled with zero policies** → nobody except the service role (used inside the edge functions) can read or write. Indexes on created_at desc, (type, created_at), visitor_id, session_id.
- **`ip_geo_cache`** (IP → geo, with fetched_at) so repeat visitors don't trigger repeat lookups. RLS on, no policies.
- **`get_stats(days)`** security-definer function returning one jsonb: totals (views, uniques, sessions, avg time-on-page), per-day series, top referrers/UTM sources, countries, browsers, OS, device types, section popularity, and the 50 most recent visits.
- Run `get_advisors` (security) after — expect clean.

## 3. Edge Functions (deployed via MCP, sources kept in `supabase/functions/`)
- **`track`** (`verify_jwt=false`; protection = origin allowlist):
  - CORS allowlist: `https://harikrishnan-pv.github.io` + localhost:5173/4173 for dev; handles OPTIONS preflight; rejects other origins (403), oversized bodies.
  - Server-side: reads user-agent + client IP (x-forwarded-for) + accept-language headers, parses UA via `npm:ua-parser-js` (browser/OS/device/bot), enriches geo from cache (on miss: ipapi.co, best-effort 1.5s timeout, then cached), inserts with service role, returns 204.
- **`stats`** (`verify_jwt=false`, custom auth): requires `x-stats-key` header (or `?key=`) matching a random `SUPABASE_STATS_KEY` secret set at deploy time → calls `get_stats` RPC, returns JSON; 401 otherwise.

## 4. Site changes
- **New `public/tracker.js`** — plain JS, no deps, no build step: sends pageview on load with full client env; `section_view` on hashchange (matches the site's `#about/#projects/...` nav); scroll milestones 25/50/75/100%; outbound/mailto/download clicks with href+text; time-on-page + max scroll on `pagehide` via `navigator.sendBeacon`. Failures silent, zero UI impact.
- **`index.html`** — one line added in `<head>`: `<script defer src="/tracker.js"></script>` (Vite copies `public/` → dist root, so it works in dev and production and fires even if the main bundle fails).
- **New `public/stats.html` + `public/stats.js`** — private, unlinked dashboard with `meta robots noindex`: asks for the stats key once (localStorage, or bookmarkable `stats.html#key=…`); 7/30/90-day range toggle; dependency-free CSS/SVG bar charts + tables for all metrics from `get_stats`. The key never appears in the repo.
- No changes to existing modules, styles, or build config.
